# Design

## Context

FastAPI проверяет поток JPEG или PNG и фиксирует исходные байты в `images.content`. PostgreSQL разрешает конфликт по имени. Миграция файловой версии переносила оригиналы по имени и размеру, поэтому старые строки могут содержать байты, которые текущая проверка Pillow отклонила бы.

## Goals / Non-Goals

**Goals**

- Добавить отдельный асинхронный воркер и защищённый маршрут миниатюр.
- Сохранить исходные байты и контракт действующих запросов.
- Восстанавливать публикацию после сбоя между фиксацией и RabbitMQ.

**Non-Goals**

- Массовая генерация миниатюр для существующих строк и выбор размера клиентом.

## Decisions

1. **Transactional outbox в строке изображения.** Новая загрузка получает уникальный UUID и признак ожидающей публикации в том же `INSERT`, что и оригинал. Частичный индекс ограничивает выборку задач ожидающими записями. Фоновый цикл FastAPI читает задания, освобождает соединение и отправляет UUID через FastStream с publisher confirms, обязательной маршрутизацией и признаком persistent. Очередь durable. Признак сбрасывается только после подтверждения. При падении после подтверждения или одновременном чтении двумя экземплярами возможна повторная отправка. Публикация сразу после фиксации в HTTP-запросе оставляла бы окно потери, а отдельная таблица outbox потребовала бы второй записи и связи для очистки.
2. **Идемпотентность по UUID.** Воркер читает оригинал по UUID только при пустой миниатюре, декодирует в потоке AnyIO и записывает результат условным `UPDATE` по тому же UUID с проверкой пустого поля. Подтверждение следует за фиксацией. Временный сбой обработки приводит к повторной доставке после короткой задержки. При ошибке декодирования неизменяемых байтов воркер атомарно очищает UUID и признак публикации, оставляя оригинал доступным. Ограничение prefetch оставляет одну генерацию на процесс. Удаление строки убирает байты и признак публикации. Уже отправленные события могут дойти до воркера, где устаревший UUID будет проигнорирован.
3. **Однокадровый PNG.** Предел 256 × 256, пропорциональное уменьшение без увеличения и удаление метаданных. Для APNG с отдельным изображением по умолчанию используется первый кадр анимации. Один защищённый маршрут опрашивается по `404` с `Retry-After: 1`. Запрет кэширования позволяет получить статус после обработки, удаления или повторной загрузки имени.
4. **Миграция и Compose.** Существующие строки сохраняют исходные байты и получают пустые поля UUID и миниатюры. Compose добавляет RabbitMQ с постоянным томом и воркер из того же образа. У API остаётся запуск миграций перед Uvicorn. Тестовый стек использует собственное имя проекта и хостовый порт через `API_PORT`.

## Risks / Trade-offs

- Одноузловый RabbitMQ хранит принятую очередь на локальном томе. Потеря тома после подтверждения может потребовать восстановления из резервной копии.
- Без брокера оригиналы остаются доступны, а очередь PostgreSQL растёт вместе с количеством новых загрузок. Старые записи сохраняют прежний контракт скачивания и удаления.
