# Image Storage

## Purpose

Предоставить клиентам защищённый HTTP API для хранения именованных изображений в PostgreSQL.

## ADDED Requirements

### Requirement: Авторизация по ключу

Все маршруты API SHALL требовать непустой заголовок `X-API-Key` с исходным ключом. Сервис SHALL сравнивать SHA-256 от полученного значения с хешем из `API_KEY_HASH`. Значение этой переменной SHALL содержать ровно 64 шестнадцатеричных символа.

#### Scenario: Исходный ключ совпадает с хешем

- **WHEN** клиент передаёт в `X-API-Key` исходный ключ, SHA-256 которого совпадает с `API_KEY_HASH`
- **THEN** сервис разрешает выполнить защищённую операцию

#### Scenario: Хеш в конфигурации отсутствует или имеет неверный формат

- **WHEN** `API_KEY_HASH` отсутствует, пуст или имеет неверный формат
- **THEN** сервис прерывает запуск

#### Scenario: Ключ отсутствует или неверен

- **WHEN** клиент обращается к маршруту изображений без ключа, с неверным ключом либо передаёт значение настроенного хеша в качестве ключа
- **THEN** сервис возвращает `401 Unauthorized` до любых действий с хранилищем

### Requirement: Допустимое имя изображения

Маршруты SHALL принимать имена в формате `[a-z0-9][a-z0-9_-]{0,63}\.(jpg|jpeg|png)` и обращаться только к файлам каталога изображений.

#### Scenario: Недопустимое имя

- **WHEN** авторизованный запрос содержит недопустимое имя, которое сопоставлено с маршрутом
- **THEN** сервис возвращает `400 Bad Request` без обращения к файлу

### Requirement: Загрузка изображения

`PUT /images/{name}` SHALL принимать исходные байты JPEG или PNG. Размер тела SHALL быть не больше 10 МиБ, а изображение SHALL содержать не больше 25 миллионов пикселей по всем кадрам. Формат файла SHALL соответствовать расширению имени. Повторная загрузка SHALL сохранять уже записанный файл.

#### Scenario: Новый файл

- **WHEN** авторизованный клиент загружает допустимое изображение под свободным именем
- **THEN** сервис полностью записывает файл и отвечает `201 Created` с заголовком `Location` для скачивания

#### Scenario: Имя уже занято

- **WHEN** авторизованный клиент загружает допустимое изображение под занятым именем
- **THEN** сервис возвращает `409 Conflict` и сохраняет исходные байты

#### Scenario: Заявленный размер превышает лимит

- **WHEN** авторизованный клиент указывает `Content-Length` больше 10 МиБ
- **THEN** сервис отвечает `413 Content Too Large` до чтения тела и создания временного файла

#### Scenario: Потоковая загрузка превышает лимит

- **WHEN** авторизованный клиент отправляет тело без `Content-Length` и фактически полученный размер превышает 10 МиБ
- **THEN** сервис прекращает чтение, удаляет временный файл и возвращает `413 Content Too Large`

#### Scenario: Изображение превышает лимит пикселей

- **WHEN** загруженный файл укладывается в лимит байтов, а изображение содержит больше 25 миллионов пикселей по всем кадрам
- **THEN** сервис возвращает `413 Content Too Large` без публикации изображения

#### Scenario: Соединение прерывается до конца загрузки

- **WHEN** клиент разрывает соединение во время передачи тела
- **THEN** сервис удаляет временный файл и не публикует изображение

#### Scenario: Некорректное изображение

- **WHEN** авторизованный клиент отправляет пустое или повреждённое изображение либо формат изображения не соответствует расширению имени
- **THEN** сервис возвращает `415 Unsupported Media Type` и новый файл недоступен для скачивания

### Requirement: Скачивание изображения

`GET /images/{name}` SHALL возвращать исходные байты изображения как вложение с типом `image/jpeg` или `image/png`.

#### Scenario: Изображение существует

- **WHEN** авторизованный клиент скачивает существующее изображение
- **THEN** сервис возвращает `200 OK`, тип изображения и сохранённые байты

#### Scenario: Изображение отсутствует

- **WHEN** авторизованный клиент запрашивает отсутствующее изображение
- **THEN** сервис возвращает `404 Not Found`

### Requirement: Удаление изображения

`DELETE /images/{name}` SHALL удалять запись изображения из PostgreSQL по имени.

#### Scenario: Изображение существует

- **WHEN** авторизованный клиент удаляет существующее изображение
- **THEN** сервис возвращает `204 No Content`, а последующее скачивание возвращает `404 Not Found`

#### Scenario: Изображение уже отсутствует

- **WHEN** авторизованный клиент удаляет отсутствующее изображение
- **THEN** сервис возвращает `404 Not Found`

### Requirement: Запуск и сохранность файлов

На машине с Docker и Compose сервис SHALL запускаться из корня проекта командами `cp .env.example .env` и `docker compose up`. Загруженные изображения SHALL оставаться доступными при пересоздании контейнера с тем же томом.

#### Scenario: Сервис пересоздан

- **WHEN** оператор после успешной загрузки останавливает сервис через `docker compose down` и снова запускает его через `docker compose up`
- **THEN** авторизованный клиент получает по тому же имени те же байты изображения

### Requirement: Хранение и перенос изображений

Сервис SHALL хранить имя как первичный ключ таблицы `images` и исходные байты в столбце `content` типа `bytea` в PostgreSQL. При первом обновлении с файловой версии миграция SHALL перенести сохранённые изображения из прежнего тома байт в байт, сохранив исходный том.

#### Scenario: Успешная загрузка подтверждает транзакцию

- **WHEN** авторизованный клиент загружает допустимое изображение под свободным именем
- **THEN** сервис возвращает `201` после фиксации одной записи в PostgreSQL

#### Scenario: Обновление с файловой версии

- **WHEN** сервис впервые запускается с PostgreSQL и прежним томом с изображениями
- **THEN** существующие файлы доступны по тем же именам с теми же байтами после миграции
