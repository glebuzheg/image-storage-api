# Асинхронная загрузка оригиналов

## Purpose

Принимать изображения с подтверждением сохранности входных байтов, записывать оригиналы через очередь и показывать статус загрузки.

## ADDED Requirements

### Requirement: Асинхронный приём оригинала

`PUT /images/{name}` SHALL принимать проверенные потоковые байты JPEG или PNG в пределах действующих лимитов. API SHALL надёжно сохранить принятые байты и зарезервировать имя вместе с заданием, затем вернуть `202 Accepted` и `Location: /uploads/{uuid}`.

#### Scenario: Брокер недоступен

- **WHEN** клиент завершает допустимую загрузку при выключенном RabbitMQ
- **THEN** API возвращает `202`, а после восстановления связи публикует задание

#### Scenario: Имя занято

- **WHEN** имя зарезервировано или оригинал уже сохранён
- **THEN** допустимая повторная загрузка возвращает `409`

### Requirement: Проверка статуса загрузки

`GET /uploads/{uuid}` SHALL требовать API-ключ и возвращать JSON с полями `status` и `image_url`. Ответ SHALL иметь `Cache-Control: no-store`. До фиксации оригинала статус SHALL быть `pending` с `Retry-After: 1`, после — `stored`. Неизвестный или удалённый UUID SHALL возвращать `404`.

#### Scenario: Оригинал ещё сохраняется

- **WHEN** клиент проверяет статус принятой загрузки до обработки
- **THEN** статус равен `pending`, а запрос оригинала возвращает `404`

#### Scenario: Воркер сохранил оригинал

- **WHEN** клиент проверяет статус после фиксации оригинала
- **THEN** статус равен `stored`, а оригинал доступен по `image_url` с исходными байтами

### Requirement: Фоновое сохранение оригинала

API SHALL публиковать UUID в устойчивую очередь `image.store` через FastStream. Воркер SHALL сохранить оригинал и назначить задание на миниатюру одной транзакцией. Издатель SHALL снимать признак публикации только для подтверждённой фазы. При временной ошибке записи воркер SHALL вернуть сообщение в очередь.

#### Scenario: Публикация оригинала подтверждена после его записи

- **WHEN** воркер записал оригинал до обновления outbox издателем
- **THEN** позднее подтверждение оставляет задание миниатюры ожидающим публикации

#### Scenario: Повторное сообщение

- **WHEN** воркер получает повтор сохранения уже записанного оригинала
- **THEN** исходные байты и состояние миниатюры сохраняются

### Requirement: Отмена и повторное использование имени

`DELETE /images/{name}` SHALL удалять принятую загрузку или сохранённый оригинал, включая его миниатюру. Воркер SHALL игнорировать UUID удалённой загрузки после повторного использования имени.

#### Scenario: Удаление до записи

- **WHEN** принятое изображение удалено и клиент использует то же имя для другой загрузки
- **THEN** старое событие не записывает оригинал поверх новой загрузки
